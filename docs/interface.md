# Интерфейсті қосу

Бұл компонент дайын есептеулерді көрсетеді; рөлдерді, кластерлерді және басымдықтарды есептемейді. Толық орнату мен тексеру жоба түбіріндегі README-де берілген.

## Windows / VS Code

Жоба қалтасындағы терминалда:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

VS Code ішінде Python кеңейтімін орнатып, `Python: Select Interpreter` арқылы `.venv` ортасын таңдаңыз. Виртуалды ортаны белсендіру міндетті емес.

## Командамен келісім

Интерфейс иесі: `app.py`, `ui/`, `requirements-ui.txt`, осы нұсқаулық.

Толық жобада аналитика кітапханалары да қажет: `pip install -r requirements.txt`.
Кеңейтілген интерфейс `src/insights.py` және `src/scenarios.py` модульдерін пайдаланады.

Пайплайн иесі нәтижелерді төмендегі жолдарға сақтайды. Файлдар жобаның түбіріне қатысты анықталады; дискідегі файлдар әр экран әрекетінде қайта оқылады. Толық есептеу аяқталған соң «Нәтижелерді жаңарту» батырмасын басыңыз. Жазуды уақытша файлдан atomic replace арқылы аяқтау ұсынылады.

| Файл | Міндетті бағандар |
|---|---|
| `data/nodes.parquet` | `gid, depth, is_seed` |
| `data/edges.parquet` | `src, dst, sum_kzt, n_tx` |
| `out/nodes_roles.csv` | `gid, role, role_score, cluster_id, priority_score, evidence` |
| `out/clusters.csv` | `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis` |
| `out/top_nodes.csv` | `rank, gid, role, priority_score, why` |

Қосымша `out/node_metrics.csv` қабылданады: `gid` және метрика бағандары. Негізгі клиент карточкасы сомаларды берілген edges файлынан есептейді, сондықтан қосымша файлсыз да жұмыс істейді. `transactions.parquet` интерфейске қажет емес; оны талдау пайплайны пайдаланады.

Идентификаторлар бүтін сан, бағалар 0–1 аралығында, CSV кодтамасы UTF-8 болуы керек. Рөлдер: `consolidator`, `transit`, `distributor`, `terminal`, `coordinator`, `peripheral`. `nodes_roles.csv` барлық клиентті, соның ішінде оқшауланған клиенттерді қамтуы тиіс. Интерфейстегі тексерулер толық пайплайн валидациясын алмастырмайды.

Басқа қалталарды қолдану:

```powershell
$env:MONEY_GRAPH_DATA = 'C:\path\to\data'
$env:MONEY_GRAPH_OUT = 'C:\path\to\out'
.\.venv\Scripts\python.exe -m streamlit run app.py
```

## Қайталанатын тексеру

1. Дерексіз іске қосыңыз: қосу нұсқауы көрсетілуі керек.
2. Үш бастапқы Parquet-ті `data/` ішіне салыңыз: граф ашылуы, рөлдердің дайын еместігі көрсетілуі керек.
3. Пайплайнның үш CSV нәтижесін `out/` ішіне салып, жаңартыңыз.
4. Бар gid енгізіңіз: карточка, көршілер, бағытталған жебелер және аударым кестесін тексеріңіз.
5. Оқшауланған gid, жоқ gid және сан емес сұрауды тексеріңіз.
6. depth=4 және шығысы жоқ клиент үшін дерек шекарасы туралы хабарламаны тексеріңіз.
7. Кластер, рөл сүзгілері, топ-лист және үш CSV жүктеуін тексеріңіз.

## Шектеулер

Рөлдер мен бағалар сыртқы пайплайннан келеді. Пайплайнды автоматты іске қосу қосылмаған. ЖИ — API кілтімен бөлек қосылатын режим. Граф бастапқыда ең көп 250 клиентті көрсетеді, шекті арттыруға болады; қысқарту болса экранда хабарланады. Клиент іздеу кластер/рөл сүзгілерінен тәуелсіз. Кіріс/шығыс — тек бақыланған желідегі сома. Графтың JavaScript ресурстары HTML ішіне енеді, көрсету үшін сыртқы CDN қажет емес. Жарияланған нұсқа жоқ.

## Жаңа аналитиканы интерфейске қосу

`ui/analytics_panels.py` аналитика иесінің нақты функцияларын пайдаланады:

- `build_node_insights(nodes_roles, node_metrics)` — қазақша карточка;
- `analyze_weight_sensitivity(nodes_roles, node_metrics)` — 64 комбинациядағы тұрақтылық;
- `simulate_node_removal(edges, nodes, gid)` — батырмамен орындалатын виртуалды сценарий.

Пайплайн негізгі төрт CSV-ге екі келісілген CSV қосады. Толық `node_metrics.csv` бар
кезде интерфейс алғашқы екі есепті дайындап, кіріс DataFrame бойынша кэшке сақтайды.
Кіріс өзгерсе кэш жаңарады. Сценарий пайдаланушы батырманы басқанда есептеледі;
басқа gid таңдалса бұрынғы сценарий жасырылып, жаңа есеп қажет болады.
Ешбір функция бастапқы деректі өзгертпейді. Толық емес snapshot болса негізгі
интерфейс жұмыс істейді, қосымша талдаудың қолжетімсіздігі хабарланады.

Карточкада `review_reason_kz`, `missing_data_kz`, `next_step_kz` нақты бағандары
қолданылады. Жүктеу кезінде `src.data_io.format_delivery_outputs` оларды
ортақ CSV келісіміндегі `reasons/limitations/next_step` атауларына бейімдейді.
Тұрақтылықта `top_k_count`, `scenario_count`, `best_rank`, `worst_rank` көрсетіледі.

«Жүктеу» бөлімінде алты пайплайн CSV-і және `sensitivity_scenarios.csv` беріледі.
Қосымша екі файлдың схемасы:

- `node_insights.csv`: `gid, reasons, limitations, next_step`;
- `ranking_stability.csv`: `gid, runs, top20_count, rank_min, rank_max`.

Екі файлды пайплайн да дискіге сақтайды. `ui/assistant_panel.py` осы файлдар мен
`nodes_roles.csv` негізіндегі `src.assistant.answer_question` функциясын көрсетеді.
API-сіз жауап жергілікті сақталған CSV-ден құрылады. «ЖИ-ді қосу» бөлімінде
провайдер, жасырын API кілті, модель және тетік бар. Қосылғанда
`answer_with_ai` бес клиентке дейінгі контекст пен ортақ тікелей алушыларды
дайындап, `src/llm.py` арқылы OpenAI немесе NVIDIA-ға бір сұрау жібереді.
Кілт чат тарихына жазылмайды; өшіру батырмасы ЖИ режимін де сөндіреді.
Жауаптың дереккөздері, провайдер/модель және нақты контекст экранда көрсетіледі.
API қатесі жергілікті жауаппен бірге ашық көрсетіледі. Файлдар жоқта негізгі граф жұмыс істейді.
Тарих соңғы 10 сұрақпен шектеледі, CSV жаңарғанда немесе тазарту батырмасымен жойылады.

Қазақша карточка, толық емес деректер, тұрақтылық, виртуалды сценарий және
клиент ауысқандағы сценарийді жасыру `checks/test_interface.py` арқылы тексеріледі.
Бұл тестте ЖИ чаты мен кілтті өшіру де тексеріледі; сыртқы API жауабы mock арқылы беріледі.

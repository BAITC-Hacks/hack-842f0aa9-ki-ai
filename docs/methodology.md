# Ақша графы: аналитика әдістемесі

## Модуль және командамен келісім

`src/analysis.py` ішіндегі `analyze(edges, nodes, transactions)` төрт pandas
DataFrame қайтарады, мына ретпен:

1. `nodes_roles`: gid, role, role_score, cluster_id, priority_score, evidence.
2. `clusters`: cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis.
3. `top_nodes`: rank, gid, role, priority_score, why.
4. `node_metrics`: gid, depth, is_seed, in_deg, out_deg, in_kzt, out_kzt,
   pagerank, truncated_by_depth және төменде сипатталған қосымша метрикалар.

Функция кіріс кестелерін өзгертпейді, файл оқымайды/жазбайды, API кілтін қажет етпейді.
Пайплайн иесі DataFrame-дарды UTF-8 CSV ретінде `out/` ішіне сақтайды.
Интерфейс `gid` арқылы байланыстырады. Баған атаулары өзгермейді.
`app.py`, `ui/` және ортақ пайплайн аналитика модулінде өзгертілмейді.

## Орта және іске қосу

~~~

NetworkX PageRank үшін SciPy керек; ол бастапқы starter тәуелділіктерінде жоқ.
Тексерілген орта: pandas 2.3.3, numpy 2.5.3, pyarrow 23.0.1, NetworkX 3.7,
SciPy 1.18.1, Streamlit 1.64.0, PyVis 0.3.2.
Толық қайталанғыштық үшін осы нұсқаларды қолдану керек:
кітапхана нұсқасы ауысқанда Louvain нәтижесі өзгеруі мүмкін.

Пайплайнға арналған мысал (бұл кодты аналитика функциясы орындамайды):

~~~python
from pathlib import Path
import pandas as pd
from src.analysis import analyze

data = Path("data")
edges = pd.read_parquet(data / "edges.parquet")
nodes = pd.read_parquet(data / "nodes.parquet")
transactions = pd.read_parquet(data / "transactions.parquet")
results = analyze(edges, nodes, transactions)

out = Path("out")
out.mkdir(exist_ok=True)
names = ("nodes_roles", "clusters", "top_nodes", "node_metrics")
for name, table in zip(names, results):
    table.to_csv(out / f"{name}.csv", index=False, encoding="utf-8")
~~~

Интерфейсті ашу:

~~~powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
~~~

## Кірісті тексеру

- Міндетті бағандар және бос мәндер тексеріледі.
- gid/src/dst бүтін типте қалады; float түріндегі идентификатор қабылданбайды.
  Бұл 2^53-тен үлкен идентификаторлардың дәлдігін сақтайды.
- nodes.gid және edges ішіндегі (src, dst) жұбы қайталанбауы керек.
  Бірдей жеке транзакциялар автоматты түрде жойылмайды.
- Барлық аударым ұштары nodes ішінде болуы тиіс.
- depth: 0–4; is_seed: bool және depth=0 белгісімен сәйкес.
- Сомалар оң және ақырлы; n_tx оң бүтін сан.
- transactions жұп бойынша біріктіріліп, edges-пен жұптары, сомасы және саны
  салыстырылады. Сомаға абсолюттік рұқсат: 0.01 KZT, салыстырмалы рұқсат: 0.
- Қате болса, түсінікті ValueError беріледі; жартылай нәтиже қайтарылмайды.
- Бос nodes қабылданбайды. Тек оқшауланған клиенттерден тұратын граф қабылданады.

## Граф және метрикалар

Алдымен барлық nodes.gid графқа енгізіледі, содан кейін бағытталған аударымдар
қосылады. Жол ретіне тәуелділікті болдырмау үшін түйіндер gid, байланыстар
(src, dst), транзакциялар (src, dst, date, sum_kzt) бойынша сұрыпталады.

- in_deg/out_deg: бірегей жіберуші/алушы саны.
- in_kzt/out_kzt: таңдаманың ішіндегі көрінетін сомалар.
- in_tx/out_tx: аударымдар саны, n_tx салмақтарының қосындысы.
- pagerank: бағытталған, sum_kzt бойынша өлшенген PageRank; alpha=0.85,
  tol=1e-10, max_iter=1000.
- betweenness: бағытталған графтағы қысқа жолдар бойынша делдалдық.
  128 түйіннен, шағын графта барлық түйіннен бағаланады; seed=42.
  Жол ұзындығы — байланыстар саны. Ақша сомасы қашықтық ретінде қолданылмайды.
- seed_payers: тікелей ақша жіберген бірегей seed клиенттер саны.
- external_clusters: тікелей көршілер кіретін, өз кластерінен басқа кластерлер саны.
- is_isolated: in_deg+out_deg=0.
- truncated_by_depth: depth=4 және out_deg=0.
- pass_through: out_kzt/in_kzt; in_kzt=0 кезінде 0 деген техникалық мән беріледі,
  бірақ pass_through_defined=False. Оны нақты қатынас деп түсіндіруге болмайды.
- balance_similarity: min(in_kzt,out_kzt)/max(in_kzt,out_kzt); екі сома 0 болса 0.
- active_days: клиенттің кірісі немесе шығысы байқалған күндер саны.
- peak_day_share: ең белсенді күндегі кіріс+шығыстың жалпы кіріс+шығысқа үлесі.
- near_inflow_out_share: кіріс болған күні немесе келесі күні жасалған
  шығыс сомасының барлық шығысқа үлесі. Шығыс жоқ болса 0.

Күн деңгейіндегі жақындық ақша көзін немесе оқиғалардың бір күн ішіндегі
ретін дәлелдемейді: бір ақша бірнеше рет сәйкестендірілмейді деген кепіл жоқ.
Бұл сома бойынша нақты ақша ізін қадағалау емес, уақыттық қосымша белгі.

Егер self-transfer болса, ол кіріс пен шығыста бір реттен саналады.
Сондықтан клиенттер бойынша in_kzt+out_kzt қосындысы желінің айналымын
екі рет санайды. Желінің айналымы — edges.sum_kzt қосындысы.

## Нормалау және шектер

N(x) = min(1, log(1+x) / log(1+Q95(x>0))).

Q95 — оң мәндердің 95-процентилі; оң мән жоқ болса N(x)=0.
Бұл жоғары сомалардың әсерін шектейді, 0-ді 0-де сақтайды.
Процентильдер барлық клиент бойынша, тек оң мәндерден бір рет есептеледі.

Рөл шектері:

- Din = max(3, ceil(Q90(in_deg>0))).
- Dout = max(3, ceil(Q90(out_deg>0))).
- Ain = Q75(in_kzt>0).
- B = Q90(betweenness>0).

Берілген файлдардағы нәтиже: Din=3, Dout=8, Ain=166819.7 KZT,
B шамамен 0.00038929534. Бұлар клиенттердің қолмен таңдалған тізімі емес;
жаңа деректе сол процентиль формулалары қайта есептеледі.
Нақты шектер `node_metrics.attrs["thresholds"]` ішінде де беріледі.
DataFrame attrs CSV-де сақталмайды; пайплайн қажет болса жеке журналға жазады.

## Рөлдер және таңдау тәртібі

Бірінші сәйкес келген ереже таңдалады:
**coordinator → consolidator → distributor → transit → terminal → peripheral**.

| Рөл | Шарт | role_score формуласы |
|---|---|---|
| coordinator | in_deg>=2, out_deg>=2, external_clusters>=2, betweenness>0 және >=B | 0.50*N(betweenness)+0.25*N(pagerank)+0.25*min(external_clusters/3,1) |
| consolidator | in_deg>=Din, in_kzt>=Ain, in_deg>=2*out_deg | 0.50*N(in_deg)+0.30*N(in_kzt)+0.20*N(in_tx) |
| distributor | out_deg>=Dout; seed болса осы жеткілікті, өзгелерде out_deg>=2*in_deg | 0.50*N(out_deg)+0.30*N(out_kzt)+0.20*N(out_tx) |
| transit | seed емес, шекарада кесілмеген, in_kzt>0, 0.7<=out/in<=1.3, near_inflow_out_share>=0.5 | 0.60*balance_similarity+0.40*near_inflow_out_share |
| terminal | seed емес, шекарада кесілмеген, in_kzt>0, out/in<=0.1 | 0.60*(1-out/in)+0.40*N(in_tx) |
| peripheral | Алдыңғы ережелердің ешқайсысы орындалмаған | Қалыпты fallback: 0.20; оқшауланған: 0.80; кесілген шекарада: 0.10 |

Шекарада кесілген клиенттің кез келген role_score мәні ең көбі 0.35.
Мұндай клиенттің байқалған көп кірісі consolidator белгісін беруі мүмкін,
бірақ оның шығысы туралы қорытынды жасалмайды.
Оқшауланған клиенттің 0.80 бағасы тек «байқалған байланыс жоқ» дегенге қатысты.

Бұл эвристикалық сәйкестік бағалары; калибрленген ықтималдық емес.
coordinator — желілік делдалдыққа кандидат, нақты ұйымдастырушы деп тану емес.
terminal — тек осы кезең мен таңдамадағы байқалған ұстап қалу белгісі.

Evidence нақты метрикалардан құрылады және 200 таңбадан аспайды.
Онда рөл ережесіне қатысты сандар, қажет кезде incomplete inflow немесе
outflow unknown белгісі көрсетіледі. Түсіндірмелер ағылшынша, рөлдер ТЗ-мен сәйкес.
Сомалар 6 маңызды цифрға дейін көрсетіледі; толық мәндер node_metrics ішінде.

## Кластерлер

Louvain тек бағытталмаған бөлек проекцияда орындалады. A→B және B→A
болса, салмақтары қосылады. Self-transfer кластер байланыстыруына қатыспайды.
seed=42, resolution=1. Оқшауланған түйіндерге жеке кластер беріледі.
Кластерлер ең кіші gid бойынша реттеліп, cluster_id 0-ден басталады.

- n_nodes: клиенттер саны.
- n_seed: seed саны.
- sum_kzt_internal: екі ұшы бір кластерде жатқан бастапқы бағытталған
  edges.sum_kzt мәндерінің қосындысы. Әр жол бір рет саналады.
- top_gids: басымдық бойынша алғашқы бес gid, нүктелі үтірмен бөлінген мәтін.
- hypothesis: басым рөл саны, шекарадағы клиенттер және coordinator кандидаттары
  арқылы берілген топ сипаттамасы; ұйымның нақты мақсаты туралы тұжырым емес.

## Тексеру басымдығы

priority_score =
0.25*N(in_kzt+out_kzt) +
0.15*N(in_tx+out_tx) +
0.15*N(in_deg+out_deg) +
0.15*N(pagerank) +
0.15*N(betweenness) +
0.15*role_support.

role_support = role_score, бірақ peripheral үшін 0.
PageRank нормалауында оқшауланған клиенттердің мәндері 0 деп алынады.
Оқшауланған клиенттің priority_score=0. Барлық баға 0–1 аралығында.

Әр қосылғыш node_metrics ішіндегі priority_flow, priority_transactions,
priority_degree, priority_pagerank, priority_bridge, priority_role бағандарында
сақталады. Олардың қосындысы priority_score-ға тең. why осы үлестерді және
рөл дәлелін көрсетеді. Бұл интерфейсте есепті қайта жазбай түсіндіруге мүмкіндік береді.

Салмақтар — қолмен белгіленген бастапқы эвристика; белгіленген оқыту дерегі жоқ.
Құрылымдық белгілер өзара байланысты болуы мүмкін, сондықтан жоғары баға
бірнеше тәуелсіз дәлел бар дегенді білдірмейді. Көрінбейтін ағындарға баға берілмейді.
Баға шекарадағы клиенттерді толық салыстырмалы етпейді.

Топта 20 клиент: priority_score кемуі, тең болса gid өсуі.
rank 1-ден басталады. Кірісте 20-дан аз клиент болса, барлығы ғана қайтарылады.

## Дерек шектеулері

Граф 81 seed-тен тек шығыс бағытында, төрт қадамға дейін жиналған.
Шілде 2026, >=5000 KZT сүзгісі қолданылған. Басқа банктер, басқа кезеңдер,
төменгі сомалар және таңдамаға кірмеген клиенттермен байланыстар көрінбеуі мүмкін.

- Seed кірісі толық емес; transit/terminal ережелері seed-ке қолданылмайды.
- depth=4, out_deg=0: terminal емес, кейінгі қозғалыс белгісіз.
- Тереңдігі төмен клиенттің де көрінетін ағыны толық шот балансы емес.
- peripheral — «қауіпсіз» деген белгі емес; рөлге дәлел жеткіліксіз деген fallback.
- Нәтиже қылмыс туралы шешім емес, тексеруге арналған құрылымдық гипотеза.

Миллион түйінде pandas/NetworkX нұсқасын сол күйі қолдану жоспарланбайды:
Parquet-ті бөліктермен оқу/SQL агрегация, sparse немесе igraph графы,
ірі компоненттер бойынша кластеризация, PageRank итерациялары және азайтылған
betweenness үлгісі қажет. Интерфейске тек таңдалған маңай беріледі.

## Тексерулер

`src/test_analysis.py` жеке аналитика тесттері:
үлкен идентификаторлар, толық қамту, кірісті өзгертпеу, шекара және seed,

distributor 43, coordinator 39. Есептеу жергілікті ортада шамамен 6.6 секунд алды

Нақты деректі жол реті өзгертілген нұсқада қайта есептеу де дәл сол нәтижені берді.

1.1 секунд алды; алғашқы іске қосылу 6.6 секунд болған.
